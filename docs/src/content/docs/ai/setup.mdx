Marginal's AI features call the vendor's API directly with a key that
belongs to you. Usage is billed by the vendor to that key; Marginal's
subscription never gates the AI.

## Pick a provider and add its key

1. Open **Settings ▸ AI** (<kbd>⌘,</kbd>) and choose the **Provider**
   under **API AI model**: Anthropic, OpenAI, Google, xAI, or Alibaba
   Cloud (with a separate entry for the China endpoint, whose keys are
   region-bound).
2. Create a key on the provider's console. **Get an API key from …** under
   the key field opens the right page:

   | Provider | Keys page |
   |---|---|
   | Anthropic | [platform.claude.com/settings/keys](https://platform.claude.com/settings/keys) |
   | OpenAI | [platform.openai.com/settings/organization/api-keys](https://platform.openai.com/settings/organization/api-keys) |
   | Google | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
   | xAI | [console.x.ai](https://console.x.ai/team/default/api-keys) |
   | Alibaba Cloud | [Model Studio console](https://modelstudio.console.alibabacloud.com/?tab=playground#/api-key) (international) or [bailian.console.aliyun.com](https://bailian.console.aliyun.com/?tab=model#/api-key) (China) |

3. Paste the key into the key field and click **Save**.

<Shot name="settings-ai" alt="The AI tab of Settings with the provider, model and effort pickers and the API key field" caption="Settings ▸ AI. A saved key shows as dots; Clear removes it." />

Each provider keeps its own key in the system keychain: the Keychain on
macOS, Credential Manager on Windows, the Secret Service on Linux. Keys
are read only inside Marginal's Rust process and never reach the
interface, a log, or a config file. **Clear** removes the selected
provider's key again; switching providers shows whether that one has a
key saved.

Typing `/login` in the AI bar (<kbd>⌘K</kbd>) opens the selected
provider's keys page and this settings tab together.

## Model and effort

**Model** lists the provider's current models. Switching the provider
resets it to that provider's default. **Other model id…** at the end of
the list takes any id the API accepts, for a model newer than this list;
it stays listed, marked *typed in*.

**Effort** trades speed for reasoning, in the provider's own terms; a
model without such a control shows *not adjustable*. Marginal sends
exactly what the setting says. The lists, as checked on 11 November 2026:

| Provider | Models (default first) | Effort |
|---|---|---|
| Anthropic | Claude Opus 5.5, Claude Sonnet 5.5, Claude Haiku 5.5, Claude Fable 5.2 | `low`, `medium`, `high`, `xhigh`, `max`; the default is `medium` on Opus 5.5 and Haiku 5.5, `high` on Sonnet 5.5 and Fable 5.2 |
| OpenAI | GPT-6.1 Sol, GPT-6 Astra, GPT-6.1 Terra, GPT-6 Luna | `low`, `medium` (default), `high`, `xhigh`, `max`; Terra and Luna also take `none` (no reasoning) |
| Google | Gemini 4 Argon, Gemini 4 Carbon, Gemini 3.8 Flash, Gemini 3.5 Flash-Lite | thinking level `low`, `medium` (default), `high`; Flash-Lite adds `minimal` and starts there. Gemini cannot stop thinking. Gemini 4 Carbon may not be open to every key yet |
| xAI | Grok 4.7, Grok 4.6, Grok 4.3, Grok 4.20 non-reasoning | `none`, `low`, `medium`, `high`, `xhigh` per model: Grok 4.7 and 4.6 always reason (`high` default), Grok 4.3 can skip it with `none`, the 4.20 non-reasoning model has no control |
| Alibaba Cloud | Qwen3.8 Max, Qwen3.7 Plus, Qwen3.8 Flash, Qwen3 Max, Qwen Plus | thinking **on** or **off** only; on by default from Qwen3.5 up, off for Qwen3 Max and Qwen Plus |

A model id you have set by other means is kept and listed too, and so is
a model you picked from an earlier version of these lists.

## When something goes wrong

The AI bar reports problems in place: a missing key, a key the provider
rejects, a rate limit, a network failure, or a request the model declined.
Each comes with the sensible next step, such as **Open Settings** or
**Retry**.
